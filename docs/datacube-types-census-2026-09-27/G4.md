## Cross-cutting observations

- **The kind-from-type default rule is written 6 times here.** `kind ?? (isNumericType(type) ? measure : dimension)` appears at snapshot.ts:110, 151 and serialize.ts:850-851, 1047-1048, 1231-1232 (also ui/column-editor.ts:894, ui/panel-column.ts:260). It contradicts infer.ts:171-172 and the snapshot.ts:176-184 doc, which say Integer defaults to dimension. Fix: one rule, fed by a numeric/fractional flag on each compiler-typed column.
- **There are three hand-written type-class tables:** `isNumericType`/`isFractionalType`/`isVariantType` (snapshot.ts:171-208) and `TEMPORAL` (serialize.ts:518), plus the Boolean string compare at serialize.ts:546. They only work because relation-type.ts:33-72 folds vocabularies into short names first. Fix: a type-class flag (numeric, fractional, temporal, variant, boolean) on each column the compiler returns (relationType / tdsColumns).
- **Group keys make a lossy round trip:** typed cell → text (`groupValue`, plan.ts:133, treeview.ts:105-117) → re-typed by `keyValue` (serialize.ts:533-549) → literal (`literal`/`temporalLiteral`). The losses are sub-second time, Decimal digits and integers above 2^53, and a missing type falls back to a String literal. Fix: the level and values queries return each key as a typed literal, or a server literal writer renders it.
- **Local-component Date-to-text formatting exists 3 times** (serialize.ts:106-113, serialize.ts:810-814, treeview.ts:111-115), and ui/menu.ts:364 reuses `temporalLiteral` for display. Every copy drops milliseconds and pads the year to 2 digits. Fix: database-rendered key text, plus a server literal writer.
- **Filter literals are spelled from the value's JS runtime type, never the column's** (serialize.ts:116-124, 271-361). A String typed into a number filter, or a Date restored from saved JSON as a string, becomes a String literal. Decimals and bigints have no representation (`FilterValue`, snapshot.ts:493-494). Fix: a server literal writer given (column type from the compiler, user text).
- **The pinned RelativeDate pivot value is a real bug.** It is turned into the key text `today` (serialize.ts:816), keyValue cannot parse it, and the result is `$x.d == 'today'`.
- **The snapshot stores types as a cache** (ColumnSpec.type, DerivedColumn.type, persisted in saved views). `typeColumns` (plan.ts:52-79) refreshes them from `lambdaRelationType`, but in three ways it is not authoritative: it silently skips when the runner returns nothing, a vanished column keeps its stale type, and new columns are ignored. Fix: make relationType the only source and treat the stored type as derived state.
- **Calculated-column function signatures and "divide (always a Float)" are hand-written type claims** (calc.ts:82-151). They are verified only by compiling the examples. Fix: the compiler's function registry (signatures and return types).
- **Group-stage completions show the pre-aggregation type** (calc.ts:220), or `undefined`. Fix: the level query's plan columns (tdsColumns) give the aggregated type.
- **Aggregates and string operators emit type-dependent Pure with no type check:** `joinStrings`, sum/average, `toLower`/`contains` (serialize.ts:141-190, 244-246, 303-361). Type errors surface only as planner refusals, and gating lives in UI files. Fix: offer operators and aggregates from compiler type facts.
- **Pivot column names are client renderings of values** (serialize.ts:739 via `groupValue` text). A StrictDate shows `T00:00:00` and Float/Decimal show JS number text. Fix: database-rendered value text.
- **Dead code:** `columnType` (snapshot.ts:676-686), `dimensionColumns`/`measureColumns` (snapshot.ts:211-218) and the duplicate `Number.isInteger` branch (serialize.ts:122) can be deleted.
