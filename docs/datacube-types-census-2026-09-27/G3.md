# G3 type census: grid, columns, viewport, format, style, chart

Files: `datacube/src/grid/grid.ts`, `src/grid/columns.ts`, `src/grid/viewport.ts`, `src/format.ts`, `src/style.ts`, `src/chart.ts`, as they are on disk on 2026-09-27, uncommitted work included.

Background checked outside the group, because several notes depend on it:
- `src/result.ts:22` has `Scalar = string | number | boolean | Date | null`. `ResultColumn.type` (result.ts:41) is documented as the compiler's Pure type name. Raw SQL is the exception: it is typed from Arrow via `pureTypeOfArrow`.
- `src/duckdb.ts:132-148` (`decimalToScalar`) and `:75-86` (`toScalar`) turn a DECIMAL or BIGINT outside the safe-integer range into a **string**. In range, it becomes a JS number.
- `src/duckdb.ts:203` (`dateOnly`) turns a DATE into a **local-midnight Date**. A TIMESTAMP becomes an instant `Date`.

So a cell reaching this group's files has already lost three distinctions: Integer vs Float vs Decimal, StrictDate vs DateTime, and a safe number vs an unsafe one (the unsafe one arrives as a string).

## Cross-cutting observations

1. **The runtime JS type stands in for the Pure type in six places:**
   - format `auto`/`text` (format.ts:260-269)
   - the tooltip (grid.ts:182-188)
   - value colours (style.ts:114-120)
   - heatmap range and colour (style.ts:292, 348)
   - chart column choice (chart.ts:46-75)
   - links (columns.ts:708)

   All of them should key off the compiler's column type, `ResultColumn.type` from the typed plan (compiler: plan columns). None of them reads it today.
2. **"Is numeric" is written three times:** style.ts:292, style.ts:348 and chart.ts:47. All three are `typeof === 'number' && isFinite`. One fact from the plan (Integer/Float/Decimal/Number) replaces all three.
3. **`Scalar` erases types before these files see them.** Integer, Float and Decimal all become `number`, or `string` when unsafe (duckdb.ts:82-85, 138-147). StrictDate and DateTime both become `Date`. So every `typeof` rule here misclassifies unsafe decimals: no negative or zero colour, no heatmap, not chartable, and a possible chart label. Server fact: the plan's column type plus exactly delivered values (database-rendered value).
4. **Decimal precision is lost twice on display:**
   - `Number(value)` coercion under a number format (format.ts:282)
   - float scale division (format.ts:292, 295)

   The declared Decimal scale is also never used for digits (format.ts:144-173, which caps `number` at 2 dp). Replace with: plan columns (type and scale) plus database-rendered value.
5. **Dates are handled three ways and interact badly:**
   - A DATE is rebuilt at local midnight upstream (duckdb.ts:203).
   - Intl renders it in the viewer's zone (format.ts:208, 215).
   - `toISOString()` renders it in UTC (grid.ts:187), which shows the previous day east of UTC.
   - Strings are JS-parsed (format.ts:276), which shows the previous day west of UTC for `YYYY-MM-DD`.

   Replace with a StrictDate/DateTime distinction from the plan and calendar-exact values from the server.
6. **`auto` on a DateTime shows the date only** (format.ts:264). `auto` cannot tell StrictDate from DateTime because both are `Date`. The plan column type fixes this.
7. **`DEFAULT_FORMAT = auto`** (format.ts:124) is the defaulting rule behind items 1, 4 and 6. The default format per column should be derived once from the plan's Pure type.
8. **Compact-number formatting exists twice:** `autoScale`/`SCALES` (format.ts:47-56, 99-109) and chart `fmt` (chart.ts:197-204, which lacks trillions, locale and grouping). The chart also ignores per-column formats, and `String(raw)` labels a Date via `Date.toString()` (chart.ts:85). The chart should render through `FormatterCache` with the grid's formats. Presentation stays client, but one copy.
9. **The chart picks its label and value columns by scanning the loaded rows' JS types** (chart.ts:63-75). Server fact: the snapshot's dimension and measure roles plus the plan column types.
10. **`LeafColumn.type` and `ColumnModel.all` are dead type carriers.** They are written at columns.ts:89, 128 and 353 and read nowhere in `src/`.
