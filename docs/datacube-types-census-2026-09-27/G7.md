## Cross-cutting observations

- **Members are text, and types are rebuilt from the text.** Ad Hoc members are `groupValue` strings (state.ts:18). They are turned back into typed filter values by `keyValue` (serialize.ts:533), which reads the snapshot column type. The rebuild loses information: Decimals not safe as JS numbers and Integers past 2^53 become String literals, DateTime milliseconds are lost, and DST fall-back local times are ambiguous. Replacement: member queries return typed cells with plan column types (`compiler: plan columns`), members keep `{value, type}`, and conditions are written by a `server literal writer`.
- **The measure type is invented.** query.ts:319 stamps every ad hoc value column 'Float', and query.ts:297 stamps labels 'String'. Meanwhile the typed plan's column types arrive in session.ts:88 and are discarded. Replacement: carry `t.columns[i].type` from each shape result (`compiler: plan columns`).
- **"Numeric means measure, default sum" is re-applied here.** outline.ts:53-58 goes through `kindOf` / `rowColumns` (snapshot.ts:108, :151), the same rule the main cube uses. Replacement: `compiler: relationType` column types plus the user's declared kind.
- **Three copies of the "is this a number" test on cell values, and they differ.** selection.ts:134 and export-rich.ts:52 require `typeof number && isFinite`; export-doc.ts:85 checks `typeof number` only. None of them consults `ResultColumn.type`, which selection.ts:173 preserves. Replacement: decide by the column's Pure type from `compiler: plan columns`.
- **Decimals are split by JS representation.** duckdb.ts sends precision-safe Decimals as numbers and the rest as strings. So the same Decimal column is summed, right-aligned and exported as ss:Type Number for some rows, and ignored, left-aligned and exported as String for others (selection.ts:134, export-rich.ts:88/139, export-doc.ts:85, query.ts:282 zero test). Replacement: typed cells (`database-rendered value`) plus the plan type.
- **Dates export through `toISOString()` in UTC.** export.ts:74 and export-rich.ts:145 do this, but a DATE is a local-midnight Date (duckdb.ts:203). East of UTC the export shows the previous day, and a StrictDate gains a time and a zone. Replacement: the server renders the typed value's text (`database-rendered value`) by Pure type (StrictDate → `YYYY-MM-DD`, DateTime with its precision).
- **The local-component date key (treeview.ts:105) and the UTC export text disagree.** The ad hoc grid, CSV and SpreadsheetML each spell one date cell differently. A single server-rendered value spelling would replace all three.
- **Member captions bypass the formatter** (query.ts:190-212, member-selection.ts:152, mode.ts:204). Dates show as raw key text. Once members are typed, captions become `stays client: presentation` through FormatterCache, or `database-rendered value`.
- **Suppression zero/missing tests are JS identity checks** (query.ts:281-289). Replacement: a typed zero test by plan type, or suppression pushed into the query.
- **HTML and Excel exports are called without formatters** (app.ts:2022/2025), so export-rich.ts falls back to `String(v)`, which prints `Date.toString()` in HTML. This is a presentation bug, but it depends on the runtime `instanceof`/`typeof` checks here and not on the column type.
- **SpreadsheetML cell types are decided per cell from JS runtime types** (export-rich.ts:137-151): Number, DateTime, or everything else as String. Booleans are never Boolean, and DateTime shows as Short Date (export-rich.ts:176). Replacement: map the Pure type from `compiler: plan columns` to the spreadsheet type (a small `other: Pure→SpreadsheetML type table`, or server-side export).
- **The CSV injection guard's number test is a regex over text** (export.ts:36/61). With a column type in hand the guard could defuse by column type; it stays client either way.
- **Text identity for members is re-implemented three times**: `same` in state.ts:122 and mode.ts:507, and `join(KEY_SEP)` keys in query.ts:249/304. All become dead once members carry a typed value or a server-issued member id.
