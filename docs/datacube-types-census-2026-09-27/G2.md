# G2 type census: filter editor, column editor, column properties panel, JSON fields, form primitives

Files (paths relative to `datacube/`), read start to end as they are on disk on 2026-09-27:
`src/ui/filter-editor.ts`, `src/ui/column-editor.ts`, `src/ui/panel-column.ts`, `src/ui/json-fields.ts`, `src/ui/form.ts`.

Where these files get their types from (checked outside G2 so the "comes from" column is accurate):
- `ColumnSpec.type` / `DerivedColumn.type` in `src/snapshot.ts`. Source columns come from `src/relation-type.ts` `pureType()`, which maps any engine or lite type name to one of `String | Integer | Float | Decimal | Number | Boolean | StrictDate | Date | DateTime | Variant` and throws on anything else (so `Timestamp` becomes `DateTime`, and `StrictTime` throws). A calculated column's type is "learned from its first result" (panel-column.ts:262-263).
- `app.ts:2374-2377` builds the filter editor's columns as `rowColumns(snapshot)` with `type: c.type ?? 'String'`, so a calculated column with no type yet reaches the filter editor as `String`.
- `snapshot.ts:171 isNumericType` = `Integer | Float | Number | Decimal`, `snapshot.ts:205 isVariantType` = `Variant | meta::pure::metamodel::variant::Variant`, `snapshot.ts:108 kindOf` / `snapshot.ts:150 rowColumns` default the kind by `isNumericType`, and `config.ts:525 numberDefaults` sets decimals by type.
- The filter value's Pure literal is written by `serialize.ts:106 temporalLiteral` / `serialize.ts:116 literal`, which read the Date's LOCAL parts. Midnight prints as `%YYYY-MM-DD`.

## Cross-cutting observations

- **Four type-name tables live in the browser.** They are `dataTypeOf` (filter-editor.ts:107), `isNumericType`/`isFractionalType`/`isVariantType` (snapshot.ts:171-206), serialize.ts:518 `TEMPORAL`, and relation-type.ts `pureType`. They drift: `dataTypeOf` still names `Timestamp` and `StrictTime`, which `pureType` never emits. The replacement is one type-family fact per column published with the compiler's relation type (or generated lite-facts), keyed by the type `lambdaRelationType` returns.
- **Operator applicability** (filter-editor.ts:122-182) and **aggregate applicability** (panel-column.ts:90-117) are hand-kept compatibility tables that restate overload resolution. The compiler's signature table (which natives accept the column's type, and what they return) would replace both. It would also fix the wrong "an aggregate keeps the column's type" rule: average and stdDev on Integer yield Float.
- **Kind-by-type** (numeric means measure) has three copies that disagree: snapshot.ts:108-111, snapshot.ts:150, and column-editor.ts:893-894 all use `isNumericType`. column-editor.ts:170 always says measure. panel-column.ts:260 says measure for every calculated column and ignores `DerivedColumn.kind` (a bug). One rule should read the compiler's type.
- **A calculated column's type is "learned from its first result"** (panel-column.ts:262-263, column-editor.ts:213-222 declares no type), which violates "types come from the compiler". The live compile in column-editor.ts:313-338 already plans the candidate, so its answer should carry `lambdaRelationType` and fill `DerivedColumn.type` and the missing Value Type check.
- **Untyped fallbacks everywhere** (invariant-4 defaults): an unknown type becomes text (filter-editor.ts:114), gets all operators (1046), gets all aggregates (panel-column.ts:101), and shows all sections (611-613). app.ts:2376 defaults to `'String'`, which makes the filter editor's untyped branches dead and gives a numeric calculated column text operators. With compiler types always present, all of these go.
- **Value guessing survives**: `parseValue`/`parseList` (filter-editor.ts:375-400) and its mirror `scalarText` re-quoting (690-691). This path can be deleted once every column is typed.
- **Filter values travel as JS values** (number/Date) and are turned back into Pure text by serialize.ts. That loses the Integer/Float/Decimal and StrictDate/DateTime distinctions and precision. The fix is a server literal writer that takes (user text, column type) and returns the Pure literal or a refusal, replacing `evaluateArithmetic` + `parseTyped` + `String(n)` + `dateText` + `temporalLiteral`.
- **Numeric precision bugs**: `String(Number(text))` rewrites user input (filter-editor.ts:1148, 1160, 1262), so large integers and long decimals change silently and `1e21` becomes `1e+21`. The comma stripping at 191 turns a decimal-comma `1,5` into 15. A bad list entry becomes the item `'NaN'` and is then dropped silently (1261-1262 with 429).
- **Date bugs**: local `new Date(y,m,d,h,mi,s)` (278-279) shifts a DST-gap time by an hour. Date vs DateTime is decided from the value being non-midnight (676-677, 687-688, and the same in serialize.ts:109-113) rather than from the column type. A StrictDate column can be given a timestamp (the date editor's "Date Time" mode, and the regex at 275). The default "today" comes from the browser's time zone, not from the database session. The date text formatter is a third copy (filter-editor.ts:247, serialize.ts:106, serialize.ts:812).
- **The JSON field picker** (json-fields.ts, json-shape.ts, and column-editor.ts:90-94, 473-488, 573-608) ships raw cells to the browser, JSON-parses them and GUESSES types and kinds, as its own UI text admits ("types are a guess"). The replacement is server-side shape inference over the column (the database's own JSON structure functions) plus `lambdaRelationType` of the chosen extraction to fix its type and default kind.
- **Number format defaults** (panel-column.ts:397, config.ts:525) choose decimals from the type NAME. The Decimal scale is dropped by `pureType`, so a `DECIMAL(18,4)` shows 2 places. The plan columns (tdsColumns / execute builder `relationalType`) carry the scale.
- **Missing type gates**: the Weight column (panel-column.ts:334-353), the heatmap (576-601) and the format kinds (137-145) are offered for every type. Once types are server facts, these would be keyed on the compiler type.
- **What genuinely stays client**: the widget choice per type family (checkbox, date picker, number box), `withCurrent`, the JSON.stringify dirty check, window integer parameters, and form.ts `numberInput` for settings. All are presentation over an already-typed column.
