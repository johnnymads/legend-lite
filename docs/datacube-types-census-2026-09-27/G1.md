## Cross-cutting observations

- **Numeric-type table (client).** `isNumericType`/`isFractionalType` (`Integer`/`Float`/`Number`/`Decimal`) drives the default dimension/measure role (#kindOf, canGroup, isMeasure, extend level) and the default number formats (renderFormats/numberDefaults). It is a client copy of the type lattice, it misses FQN spellings, and snapshot.ts:176-184 contradicts how `kindOf` uses it. Replace it with a compiler-supplied type (relationType) plus one server-side "numeric?" fact per column, or a server-declared role.
- **Per-cell `typeof` numeric tests** are separate copies of "is this column numeric": selection stats (selection.ts:134), heatmap range (style.ts:292) and heatmap colour (style.ts:348). They look at JS values, not at the column's type, so DECIMAL/BIGINT carried as strings silently drop out. Replace them with the leaf's plan column type (tdsColumns / execute builder).
- **Pivot-leaf formats come from the source column's type, not the aggregate's** (710-728). count/avg change types, and a measure named apart from its column gets no default. The typed plan already knows each leaf's type, so use plan columns.
- **Three defaulting branches invent types:** `'Derived'` (762/764, not a Pure type), `'String'` for the filter window (2376), and `'String'` via menu.ts:747 for the context menu (fed `undefined` from 1388). With the compiler's relationType there is always a type, so all three should become hard failures.
- **Group-stage calc columns are typed only after a query runs** (`#adoptGroupStageTypes`, 2569-2581), because `controller.compile` returns `{pure, refusal}` and drops the type the compiler computed (2321; cube.ts:277). Returning the lambdaRelationType from compile (or typing the level query before running) removes the one-render window where formats, filter operators and panel types are wrong.
- **The Variant field shape is learned from 1,000 sampled rows** (121-122, 2341-2358). It is the only DERIVE-from-data site in this file and needs a server fact: Variant path/type inference done by the database or the compiler.
- **Variant is recognised by a two-spelling string compare** (`isVariantType`, used at 1531). That is a type-name table on the client, and a single spelling from the compiler would remove it.
- **Group and pivot keys travel as strings.** RowPath and `PivotColumn.tuple` are `string[]`, so the tree filter value (1368), the drill-through literals (1930) and the header/panel labels (802, 1701-1712) all start from client-stringified keys. The typed literal has to be rebuilt downstream. Typed key cells from the database plus a server literal writer would replace this string round trip.
- **Cell → filter value is an unchecked cast** (`raw as FilterValue`, 1377). Whatever the reader made of a DATE (a local-midnight vs UTC `Date`) becomes the filter literal. A server literal writer fed the typed cell would remove the conversion.
- **Saved views persist type names and typed filter values** (2117, 2141) and restore them as state (2169-2171) before any compiler check. Types should be re-derived from the compiler on load, and only the user's choices persisted.
- **Type flow that is already correct:** step-0 types arrive in `view.snapshot` (849), and `schemaChanges` (2584-2591) reports compiler type drift. That shows the target shape: the controller brings compiler facts and app.ts only adopts or displays them.
- **Pure presentation that stays client-side:** `toLocaleString`/`toFixed`/`toLocaleTimeString` on metadata (266-267, 909, 996, 2786, 2789), selection-stat `fmt` (3059-3062, which ignores column formats and decimals), and export filename stamps (2005, 2115).
- **Rules app.ts only delegates:** the type-driven rules behind the grid render (893), CSV/Excel/HTML/PDF/text export (1997-2035), charts (1980-1981), drill literals (1930) and the menu's operator table (menu.ts:747). They belong to the other groups' censuses and are joined here by call site.
